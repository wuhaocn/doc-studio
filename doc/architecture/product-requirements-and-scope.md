# 在线文档系统产品需求与范围

## 1. 文档定位

本文档是 Memora 当前阶段的产品基线文档。

它是以下事实的唯一来源：

- 当前产品定位
- 当前产品设计
- 目标产品设计
- 范围与功能边界
- 角色、场景与成功标准

---

## 2. 产品定位

Memora 当前定位为：

`面向团队与个人知识管理场景的在线文档系统`

当前主产品路径聚焦：

- 多租户工作区隔离
- 知识库管理
- 文档树管理
- 阅读 / 编辑双模式
- 版本历史
- 受控阅读与权限边界

当前不定位为：

- 通用 CMS
- 大而全协作办公套件
- 内置 AI 对话 / 推理产品
- 资源库优先平台
- 通用块编辑器平台
- 独立桌面产品线

---

## 3. 产品目标

### 3.1 当前阶段目标

当前阶段只服务一条主链路：

`login -> workspace -> knowledge base -> document tree -> reading/editing -> versions -> permissions`

目标不是铺广，而是把这条链路做得稳定、易理解、可扩展。

### 3.2 当前目标形态

Memora 当前目标产品形态应是：

`知识库 + 文档工作区 + 内容资产沉淀层`

当前阶段重点应具备：

- 知识治理能力
- 清晰的信息结构
- 稳定的阅读与编辑体验
- 可靠的版本与恢复机制
- 明确的权限与受控阅读边界
- 面向外部 AI 产出内容的稳定承接能力

### 3.3 外部 AI 与 Memora 的关系

Memora 的目标不是在系统内部集成 AI 对话或模型推理。

更合理的定位是：

- 外部 AI、人工编辑器、脚本和浏览器工具是上游内容生产者
- Memora 是内容落库、治理、展示、分享和消费的平台
- AI 产出的 `Markdown`、`HTML`、富文本和纯文本应能稳定进入知识库
- 同一份内容在阅读、分享、版本、搜索和开放 API 中应保持一致语义

这意味着当前阶段要解决的核心问题不是“做一个 AI 入口”，而是“让外部 AI 生成内容成为系统内的一等知识资产”。

## 4. 用户角色

### 4.1 租户管理员

关注：

- 管理工作区
- 管理知识库
- 管理成员与权限
- 管理受控阅读边界

### 4.2 知识库负责人

关注：

- 维护知识结构
- 管理目录与文档
- 保证文档质量
- 管理知识库级成员与权限

### 4.3 编辑者

关注：

- 创建与维护文档
- 调整目录结构
- 生成与查看版本

### 4.4 阅读者

关注：

- 快速找到内容
- 阅读有权限的文档
- 查看最新有效版本
- 通过受控阅读入口直达内容

## 5. 当前产品设计

### 5.1 当前产品闭环

当前活跃闭环：

`login -> workspace -> knowledge base -> document tree -> reading/editing -> versions -> permissions`

下一阶段应补齐的内容闭环：

`external generation -> import/api write -> document rendering -> governance -> publish -> downstream consumption`

闭环要求：

- 用户能查看自己加入的工作区并切换当前工作区
- 用户能从工作台进入任意有权限的知识库
- 用户能从工作区统一搜索入口跨知识库找文档
- 用户能在知识库内创建、整理、阅读、编辑文档
- 每次正文更新都生成版本记录
- 删除后的知识库和文档应保留恢复路径
- 阅读链接只是直达入口，不放宽权限
- 受控分享只是临时分发，不替代正式发布
- 正式发布应提供稳定 URL、可长期访问和可持续更新语义
- forbidden、not found、error 状态明确可见

### 5.2 当前信息架构

当前结构：

- tenant / workspace
- knowledge base
- document tree
- 独立阅读页
- 独立编辑页
- 受控分享页

当前页面分层原则：

- 工作台首页负责继续工作和知识库进入，不默认承担完整治理后台职责
- 顶栏只保留当前页面上下文、统一搜索、工作区切换和账号动作
- 知识库详情页默认突出目录整理和文档舞台，治理信息按需展开
- 开放接入、会话治理、审计留存属于治理层，不应长期挤占写作首屏

当前页面集合：

- 登录页
- 工作台首页
- 工作区管理页
- 工作区统一搜索页
- 知识库详情页
- 文档阅读页
- 文档编辑页
- 受控分享页

### 5.3 当前核心功能

#### 工作台

- 当前租户工作台聚合
- 已加入工作区列表与工作区切换
- 最近编辑文档入口
- 知识库列表入口
- 知识库回收站入口
- 轻量概览信息
- 租户治理动作入口
- 顶部统一搜索入口
- 当前会话、管理员工作区设备概览、最近审计与留存治理按需展开

#### 知识库

- 知识库列表与详情
- 创建 / 编辑 / 删除 / 恢复
- 知识库级权限覆盖
- 知识库成员配置

#### 文档

- 统一文档 / 文件夹模型
- 文档树浏览
- 创建 / 重命名 / 移动 / 删除 / 恢复
- 知识库内文档回收站入口
- 拖拽排序与批量整理
- 独立阅读页
- 独立编辑页
- 阅读链接复制

#### 版本

- 自动版本快照
- 版本列表
- 按版本回滚
- 基础 diff

#### 权限

- Owner 注册、登录、登出与当前 session
- 工作区邀请与接受邀请
- 租户角色控制
- 知识库级权限覆盖
- 前端最小权限感知
- 关键操作审计与最近记录查看

#### 开放接入

- 独立治理页
- Service Account 与 API key 生命周期
- 逐知识库 `READ / WRITE` 作用域
- 开放文档接口的最小接入配置
- 按来源定位文档与按视图消费文档的最小读取能力

#### 分发

- 文档级受控分享
- 分享过期 / 撤销 / 访问码
- 公开分享只读页
- 正式发布与公开站点基线已落地：知识库站点配置、文档稳定 slug 和公开只读页已接通

### 5.4 内容资产化能力清单

围绕“外部 AI 内容进入 Memora”这一目标，下一阶段产品能力应明确收口为以下几类：

| 能力域 | 目标能力 | 产品要求 |
| --- | --- | --- |
| 内容进入 | 手工创建、粘贴、导入、API 写入 | 用户或上游工具可用 `RICH_TEXT`、`MARKDOWN`、`HTML` 进入系统，不要求先转成富文本 |
| 内容格式 | 格式成为正式语义 | `format` 不再只是备注字段，而是决定编辑、渲染、分享和消费方式的正式能力 |
| 内容展示 | 阅读页、预览、分享一致 | 同一文档在知识库详情、独立阅读页、公开分享页和嵌入式只读页中显示一致 |
| 内容治理 | 版本、搜索、摘要、审计一致 | 不同格式的文档都可生成版本、参与搜索、被摘要、被审计 |
| 内容分发 | 受控分享与外部消费 | 文档可被分享给外部阅读者，也可被对话框、浏览器或脚本作为只读内容消费 |
| 正式发布 | 稳定 URL 与站点化消费 | 文档应能从“临时分享”升级为“正式发布”，支持稳定 slug、站点首页和长期访问 |
| 来源追踪 | 外部来源可持续同步 | 外部 AI 或脚本写入应能保留 `sourceExternalId / sourceRevision`，避免重复创建和无意覆盖 |
| 内容边界 | 文档与应用分离 | `HTML 文档` 是文档格式，`HTML 应用` 不是当前主线能力，不能混在一起 |

### 5.5 当前成熟度判断

基础较稳：

- 多租户边界
- 多知识库模型
- 文档树管理
- 基础阅读与编辑
- 版本快照与回滚
- 删除恢复基础

可演示闭环：

- 工作台
- 工作区切换
- 工作区统一搜索 V1
- 知识库管理
- 知识库级权限管理
- 删除与恢复
- 阅读链接
- 关键操作追踪
- 首页信息架构已收口为“继续工作优先，治理按需展开”

尚未生产化：

- 完整权限模型
- 更完整会话治理
- 搜索质量与索引化
- 独立归档服务与自动化批量治理
- 更细开放接口范围与协作能力
- 外部 AI 生成内容的统一格式语义与展示链路
- 正式发布、站点导航与公共消费模型

## 6. 目标产品设计

### 6.1 目标定位

目标不是“再做一个 Notion”。

更合理的目标是：

`具备企业边界、清晰知识库结构、内容资产治理和轻发布能力的在线文档平台`

### 6.2 目标信息架构

建议目标结构：

- tenant / workspace
- knowledge base
- document tree
- reader surface
- editor surface
- publishing surface
- public site surface

### 6.3 目标能力域

#### A. 知识管理

- 多知识库
- 模板
- 标签 / 分类
- 归档 / 回收站
- 文档引用关系

#### B. 阅读与编辑

- 阅读页
- 编辑页
- 版本历史
- 对比与恢复
- 评论 / 批注能力预留

#### C. 权限与发布

- 租户级权限
- 知识库级权限
- 文档级例外权限
- 受控阅读入口
- 对外发布与撤销

#### D. 搜索与发现

- 工作区搜索
- 知识库内搜索
- 标题与正文搜索
- 结果聚合与跳转

#### E. 轻发布与公开消费

- 知识库级站点配置
- 文档发布状态流转
- 稳定公开 slug
- 公开站点首页 / 详情页
- Feed / Embed / API 只读消费预留

### 6.4 内容资产化能力清单

从目标产品设计看，`Markdown / HTML / 富文本` 应被视为文档内容格式，而不是临时兼容输入。

最低目标能力应包括：

- `RICH_TEXT`、`MARKDOWN`、`HTML` 三种正式文档格式
- 文档创建、编辑、分享和 API 写入都必须显式理解并传递格式
- `Markdown` 文档可直接阅读、分享、版本化和 API 读取
- `HTML` 文档可在受控白名单内直接展示、分享和版本化
- 外部 AI 或脚本可通过 `Service Account / API key` 直接创建和更新文档
- 外部消费方可通过阅读页、分享页或 API 稳定消费同一份内容
- 正式发布应与受控分享分离，并使用稳定站点 slug / 文档 slug
- 知识库应可作为轻量站点容器，对外承载首页、列表页和详情页

### 6.5 必改项

如果要把 AI 产出内容真正收口为知识资产，以下能力属于必改项：

- 明确定义 `format`，并把它提升为正式产品语义
- 统一阅读页、知识库预览、公开分享页的渲染规则
- 提供 `Markdown / HTML` 的直接写入路径，至少覆盖创建、导入和 Open API
- 让版本、搜索、摘要、权限和审计都基于统一内容语义工作
- 把 `分享` 和 `发布` 明确拆成两条不同产品线
- 增加知识库级站点配置、文档级发布状态和公开 slug 模型
- 引入服务端统一 `renderedHtml`，避免公开消费完全依赖前端运行时渲染
- 为 AI 接入补 `upsert / batch-upsert / sourceRevision / 幂等` 语义
- 明确“文档格式展示”和“应用运行”是两条不同能力线

### 6.6 可延后项

以下方向可以保留为后续能力，不应阻塞当前内容资产化 MVP：

- 内置 AI 对话入口
- 浏览器插件、对话框一键保存、剪藏器等上游工具形态
- 自定义域名、RSS / Feed、SEO 深化和多站点主题系统
- 可执行 `HTML / JS` 应用运行时
- 实时协作、评论、批注
- 更复杂的模板、标签、引用关系

## 7. 范围边界

### 7.1 当前范围内

- 工作台
- 知识库管理
- 文档树管理
- 阅读 / 编辑双页
- 受控分享
- 版本快照与回滚
- 最小权限控制

### 7.2 暂不纳入当前基线

- AI 问答主入口
- 资源库主入口
- 技能市场
- 通用项目管理协作
- 实时多人协同编辑
- 可执行 `HTML / JS` 应用运行时
- 独立桌面产品线

---

## 8. 成功标准

当前阶段至少要回答清楚：

- 用户能否稳定进入工作台并进入知识库
- 用户能否稳定管理文档树
- 用户能否稳定阅读、编辑并生成版本
- 外部 AI 生成的 `Markdown / HTML` 内容能否稳定进入系统并被直接展示
- 用户能否明确知道谁能读、谁能改
- Web 端是否已经具备清晰、连续、易理解的主操作流

如果这些问题答不清楚，说明当前产品闭环还没有完成。
