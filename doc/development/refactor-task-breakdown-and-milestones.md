## 2. 当前执行口径

### 2.1 主链路

当前仍围绕这条主链路推进：

`tenant -> knowledge base -> document tree -> reading/editing -> versions -> permissions`

### 2.2 闭环拆分

为避免后续排期和实现继续混线，当前按以下四层闭环拆分：

- 主体进入产品闭环
- 内部知识生产闭环
- 受控分发闭环
- 机器接入闭环
- 轻发布与公开消费闭环

### 2.3 默认实施决策

- `注册` 按 `Owner Signup` 实现
- `分享` 按 `受控外部只读文档分享` 实现
- `API key` 按 `Service Account / API Key` 实现
- `删除恢复` 按 `软删除 + 回收站 + 恢复` 实现
- 普通成员不开放公共注册，只能通过邀请加入
- 本轮不做实时协作、评论批注、AI 主入口、桌面同步、模板 / 标签体系

| 阶段 | 目标 | 关键输出 |

## 4. P0 底座收口

P0 目标：

`把当前系统从“可演示”推进到“边界不自相矛盾”`

### 4.1 T0-01 聚合权限谓词收口

任务：

- 修正 `GET /api/v1/documents` 在未传 `knowledgeBaseId` 时的权限过滤
- 所有跨知识库聚合查询统一继承知识库读权限
- 为后续搜索接口抽出可复用的权限谓词

交付结果：

- 全局文档列表不会返回用户无权访问的知识库文档
- 工作台、搜索、后续外部 API 可以复用同一权限边界

验收标准：

- 受限知识库中的文档不会出现在全局列表
- 权限过滤逻辑存在统一入口，而不是散落在多个接口里

### 4.2 T0-02 删除与恢复语义补齐

任务：

- 为 `document`、`knowledge_base` 补 `deleted_at`、`deleted_by`
- 明确保留 `status=0` 作为软删除状态
- 为后续回收站和恢复流程保留必要元数据

交付结果：

- 删除动作不再只有“看不见了”的结果语义
- 恢复流程具备基础数据前提

验收标准：

- 删除后对象不可见
- 删除对象保留恢复所需元数据
- 删除不破坏租户和知识库边界

### 4.3 T0-03 错误语义统一

任务：

- 统一 `401 / 403 / 404 / 409` 的业务语义
- 明确冲突场景的产品化提示
- 前后端统一处理会话失效、无权访问、对象不存在、唯一键冲突

交付结果：

- 权限相关反馈一致
- 创建和更新冲突具备稳定提示

验收标准：

- 未登录返回 `401`
- 无权限返回 `403`
- 不存在或当前主体不可见返回 `404`
- slug/path/唯一键冲突返回 `409`

### 4.4 T0-04 权限回归测试

任务：

- 补受限知识库对全局文档列表不可见测试
- 补删除后不可见测试
- 补恢复后重新可见测试
- 补后续搜索结果按权限过滤的测试骨架

交付结果：

- 后端具备权限聚合相关最小自动化保障

验收标准：

- P0 新增风险点全部具备测试覆盖

### 4.5 T0-05 Canonical 文档同步

任务：

- 回写计划文档中的阶段门槛和默认决策
- 修正文档里“阅读链接”等于“分享”的误导性表述
- 保证 README、产品基线、技术基线、计划文档口径一致

交付结果：

- 后续评估和排期不再依赖口头解释

验收标准：

- 当前边界在 canonical 文档中可被单点确认

## 5. P1 身份与进入产品

P1 目标：

`让系统不再依赖 demo 主体进入产品`

### 5.1 T1-01 用户模型落库

任务：

- 新增 `user`
- 新增 `user_password`
- 新增 `user_session`
- 新增 `tenant_invite`
- 将 `tenant_member.user_id` 正式绑定到真实用户主体

交付结果：

- 用户、密码、会话、邀请具备独立数据模型

验收标准：

- 不依赖 seed 用户也能建立工作区和会话

### 5.2 T1-02 Owner Signup

任务：

- 新增 `POST /api/v1/auth/register-owner`
- 一次完成 `user + tenant + tenant_member(OWNER)` 创建
- 初始化当前工作区基础信息

交付结果：

- 新环境可由管理员自主开通工作区

验收标准：

- 注册完成后可直接进入工作台

### 5.3 T1-03 成员邀请加入

任务：

- 新增 `POST /api/v1/tenants/current/invites`
- 新增 `POST /api/v1/invites/accept`
- 明确邀请有效期、状态和失效规则

交付结果：

- 普通成员通过邀请加入租户，而不是公共注册

验收标准：

- 未受邀用户不能直接加入工作区
- 有效邀请可完成加入流程

### 5.4 T1-04 登录与会话

任务：

- 实现真实 `login`
- 实现真实 `logout`
- 实现 `refresh`
- 实现 `session`
- 替换 demo token 语义

交付结果：

- 主链路不再依赖 `demo:{tenantId}:{userId}`

验收标准：

- 登录后可访问受保护页面
- 登出后会话失效
- 会话过期可被前端正确感知

### 5.5 T1-05 Web 身份流

任务：

- 新增管理员注册页
- 新增邀请接受页
- 收口登录页、登出行为、会话失效处理
- 清理仅清本地 token 的登出逻辑

交付结果：

- Web 端具备完整主体进入流程

验收标准：

- 从空环境出发，管理员可注册、登录、邀请成员、成员接受邀请并登录

### 5.6 T1-06 P1 阶段验收

验收链路：

- 管理员注册工作区
- 管理员登录
- 管理员创建知识库
- 管理员邀请编辑者
- 编辑者接受邀请并登录

通过标准：

- 全链路不依赖 seed 身份

## 6. P2 内部知识产品闭环

P2 目标：

`把当前文档工作区推进到可用的内部知识产品`

当前状态：

- `T2-01` 到 `T2-06` 已完成基础版落地
- 当前重点从“是否存在能力”切到“验证是否稳定、边界是否一致”
- P2 完成不代表已经达到正式生产化

### 6.1 T2-01 知识库权限交互收口

任务：

- 强化知识库成员列表
- 强化角色变更
- 支持移除成员
- 明确只读 / 编辑 / 管理态的 UI 和错误反馈

交付结果：

- 管理员可清晰配置知识库边界

验收标准：

- 权限变更后，读写能力和界面反馈同步变化

### 6.2 T2-02 文档树主流程收口

任务：

- 新增目录
- 新增文档
- 重命名
- 移动
- 排序
- 批量操作
- 删除
- 恢复

交付结果：

- 文档树从创建到恢复形成完整日常操作闭环

验收标准：

- 常见文档树操作不需要额外绕路

### 6.3 T2-03 版本行为收口

任务：

- 保持正文变化才生成版本
- 强化版本对比体验
- 强化回滚反馈
- 记录回滚前快照和回滚后状态

交付结果：

- 用户能理解“版本”和“恢复”的边界

验收标准：

- 元数据更新不误生成版本
- 正文回滚不破坏原历史链

### 6.4 T2-04 删除恢复体验收口

任务：

- 校验不同角色的回收站入口与恢复权限
- 增加恢复冲突提示
- 统一工作台与知识库内的恢复反馈
- 补删除后、恢复失败后的状态说明

交付结果：

- 回收站从“基础可用”推进到“权限、状态、反馈一致”

验收标准：

- 管理角色与写角色只看到自己可执行的恢复入口
- 恢复失败时用户能明确知道失败原因
- 工作台与知识库页的删除恢复反馈保持一致

### 6.5 T2-05 搜索 V1

任务：

- 新增已加入工作区列表与工作区切换
- 新增工作区统一搜索入口
- 支持 `title + contentText`
- 按知识库分组展示结果
- 结果跳转到阅读页或编辑页

交付结果：

- 搜索和工作区切换成为工作区级主入口能力，而不是局部筛选或重新登录绕路

验收标准：

- 用户可在多个工作区间切换，并保持当前 session 语义一致
- 用户可在租户内稳定找到知识
- 搜索结果继承知识库权限边界
- 搜索结果不混入目录节点

### 6.6 T2-06 状态页与反馈收口

任务：

- 补 `forbidden`
- 补 `not_found`
- 补 `deleted`
- 补 `expired`
- 补 `empty`
- 补只读编辑拦截与知识库禁止态说明
- 强化阅读态 / 编辑态 / 禁止态反馈

交付结果：

- 用户能理解当前页面为什么可用、不可用或不可达

验收标准：

- 状态反馈不再只依赖 toast 或 console

### 6.7 T2-07 P2 阶段验收

验收链路：

- owner 登录
- 切换到另一个已加入工作区
- 在当前工作区执行统一搜索
- 创建知识库
- 邀请 editor
- 创建文档
- 编辑正文
- 查看版本
- 删除文档
- 回收站恢复
- 搜索命中
- viewer 只读访问

通过标准：

- 内部知识生产闭环成立

## 15. 验收原则

每一阶段验收都应围绕闭环，而不是围绕新增模块数量。

正确的验收问题应该是：

- 主体能不能进入产品
- 能不能管理知识库
- 能不能管理文档树
- 能不能编辑并回看版本
- 能不能恢复误删内容
- 能不能找到知识
- 能不能控制谁能看、谁能改
- 能不能追查谁改了什么

如果这些问题答不清楚，再多外围模块也没有产品意义。
